# AsBoljam: вебтен кейін мобильді қосымша жасау промпты

Сен іске қосылған AsBoljam backend-ін қолданатын мобильді қосымшаны әзірлейсің. Алдымен веб-жобаның README, нақты OpenAPI, PROGRESS, қауіпсіздік шешімдері мен іске қосылған API-ін оқып тексер. Бұл жинақтың бастапқы күйінде web/API әлі жоқ; олар жасалып, тесттен өткенше мобильді интеграция дайын деп айтпа.

Ұсынылған бағыт — React Native + Expo + TypeScript. Бұл жаңа native клиент болады: Next.js беттерін сол күйі native компоненттерге көшірме. packages/api-client-тегі API типтері, домендік ұғымдар, аудармалар және design tokens ортақ қолданылады. ML мен сатып алу есептері серверде қалады. API-ді web-тен бөліп, екінші бизнес-логика көшірмесін жасама.

Негізгі тіл қазақша, қосымша тіл орысша; currency KZT, ұйымның timezone параметрі қолданылады. Телефонда 5 негізгі бөлім: Шолу, Болжам, Сатып алу, Қойма, Тағы. Manager өз бөлімшесінің жоспарларын қарайды және онлайн болғанда бекітеді. Қойма қызметкері қор кесіндісін қарайды; камера/штрихкод/нақты қабылдау модулі тек backend келісімшарты дайын болған соң қосылады.

Бастапқы сценарийлер: кіру; бөлімше ауыстыру; шолу; болжам тізімі/деталі; сатып алу тізімі/деталі; тапшылықты растау; expected_version арқылы approval; қор партиясын қарау; профиль; шығу. Планшетке split-view міндетті емес. Құпия дерек пен толық кестені push-хабарламаға салма. Push бастапқы талап емес.

Web cookie сессиясын native storage-ға механикалық көшірме. Мобильді аутентификация үшін backend-те арнайы қауіпсіз flow жобалап, қысқа мерзімді access token, rotation/revocation бар refresh token және OS secure storage қолдан. Токендерді AsyncStorage-да не log-та ашық сақтама. Native flow-ды іске қосу OpenAPI нұсқасын және қауіпсіздік тесттерін жаңартуды талап етеді.

Offline MVP: тек интерфейс қабығы, байланыс жоқ ескертуі және қажет болса пайдаланушының келісімімен минимал read-only cache. Кэштегі дерекке уақыт/ескіру белгісі қой. Сатып алу жоспарын бекіту, қабылдау, дерек импорттау немесе тапсырыс жіберу offline кезекте үнсіз орындалмасын. Қайта қосылғанда сервер нұсқасы басым; 409 conflict-та қайта қарау сұралсын. Шығу кезінде кэш тазалансын.

Демо SYNTHETIC белгісі web-тегідей сақталсын. Сценарий күні 01.01.2026 болса, телефонның бүгінгі күнімен алмастырма. Жеті/он төрт күндік функция іске асырылмаған болса, көрсетілмесін не келесі кезең деп белгіленсін. p10–p90 аралығын 90% дәлдік деме, шығын үнемін ойдан шығарма.

Нәтиже: apps/mobile коды; ортақ API типтері; .env.example; dev build іске қосу нұсқаулығы; нақты құрылғы/эмуляторда орындалған тексерулер; қате/permission/stale/offline күйлері; secure storage және logout тесттері; approval idempotency және branch-isolation тесттері. Android/iOS build нақты орындалмаса, APK/IPA дайын деп айтпа. Store жариялау, әзірлеуші аккаунты, signing және төлемдер пайдаланушының бөлек рұқсатынсыз жасалмайды.

Алдымен web API-дің ағымдағы күйін тексер; жетіспейтін native auth endpoint-терін белгіле; содан кейін шағын вертикалды сценарийді — кіру → шолу → жоспар деталі — жүзеге асыр.
