# Predas: демонстрация на три минуты

**Все данные в демонстрации — СИНТЕТИЧЕСКИЕ учебные данные. Они не принадлежат реальному заведению.**

Показываем реальный интерфейс, расчёт через API и worker, сохранение фактов и решение управляющего. История исходного набора заканчивается **31.12.2025**, прогноз и срез остатков относятся к **01.01.2026**. Дата компьютера не заменяет дату учебного сценария. Введённые при закрытии дня продажи тоже синтетические; они не становятся доказательством точности или экономии реального кафе.

## 1. Подготовить отдельный стенд

Нужны Node.js 24, Python 3.13, зависимости из `package-lock.json` и `requirements.lock`, Playwright, браузер и FFmpeg. Команды выполняются из корня **отдельного checkout репозитория**, выделенного для демонстрации. На портах **3000** и **8000** не должно быть чужого стенда. Vite на 3000 проксирует `/api` в API на `127.0.0.1:8000`; worker запускается отдельным процессом.

### База данных: обязательное условие

**Никогда не открывать, не мигрировать, не переинициализировать и не менять `data/asboljam-kz.sqlite`.** Не использовать и другую обычную рабочую базу. Для показа создаётся новый каталог `.cache/battle-<случайный идентификатор>` и новая база `runtime.sqlite` внутри него. Не копировать туда реальные данные.

`DATABASE_URL` должен быть задан **до запуска** миграции, seed, API и worker и одинаков у всех этих процессов. Присваивание переменной в новом терминале не меняет базу уже работающего API. Скрипты подготовки и записи требуют явного `PREDAS_DEMO_ISOLATED=1`: это подтверждение оператора, что он проверил запуск всех сервисов с указанной отдельной базой. Проверка пути на стороне скрипта сама по себе не доказывает конфигурацию чужого процесса. Если происхождение работающего стенда неизвестно, **остановиться до регистрации или загрузки данных**.

Не останавливайте чужие процессы ради свободного порта. Договоритесь об освобождении портов или используйте другую машину. Команды `stop` ниже относятся только к процессам, запущенным из этого checkout.

### Windows / PowerShell

В одном терминале из корня отдельного checkout:

```powershell
$demoRoot = Join-Path (Get-Location).Path ('.cache/battle-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $demoRoot -ErrorAction Stop | Out-Null
$demoDatabase = Join-Path $demoRoot 'runtime.sqlite'
if (Test-Path -LiteralPath $demoDatabase) { throw 'Нужна новая демонстрационная база' }
$env:DATABASE_URL = 'sqlite:///' + $demoDatabase.Replace('\', '/')
$env:ASBOLJAM_ENV = 'local'
$env:DEMO_DATASET = 'kz'
$env:COOKIE_SECURE = 'false'
$env:ALLOWED_ORIGINS = 'http://localhost:3000,http://127.0.0.1:3000'
$env:ASBOLJAM_SELF_REGISTRATION = 'on'
$env:WEATHER_PROVIDER = 'off'
$env:LOKY_MAX_CPU_COUNT = '1'
# Вывод Python захватывается переменной, пароль не выводится в консоль.
$env:DEMO_PASSWORD = (& python -c "import secrets; print(secrets.token_urlsafe(32))")
.\scripts\start.ps1 -Install
Remove-Item Env:DEMO_PASSWORD
```

Запуск устанавливает зависимости, мигрирует и заполняет **только явно выбранную новую базу**, затем поднимает API, worker и web. Первичная установка может занять несколько минут; она не входит в три минуты выступления. Случайный `DEMO_PASSWORD` передаётся seed только через окружение, чтобы тот не выводил одноразовый пароль. Это отдельная служебная учебная организация: для питча используется кабинет, созданный `prepare_battle_demo.mjs`.

Проверьте, что запуск завершился без ошибки, указанный файл базы создан, все три процесса принадлежат этому запуску, а в `.cache/logs/*.err.log` нет ошибок старта:

```powershell
Get-Content .cache/processes.json -Raw
Get-Content .cache/logs/api.err.log, .cache/logs/worker.err.log, .cache/logs/web.err.log
Invoke-RestMethod http://127.0.0.1:8000/api/v1/ready
Invoke-WebRequest http://localhost:3000 -UseBasicParsing | Select-Object StatusCode
git check-ignore .cache/battle-demo-login.json
# Только после проверки именно этого запуска:
$env:PREDAS_DEMO_ISOLATED = '1'
npx.cmd playwright install chromium ffmpeg
node scripts/prepare_battle_demo.mjs --lang ru
```

Ответ `/ready` должен быть `ready`, web — HTTP 200; эти ответы подтверждают доступность, но не заменяют проверку того, с какой базой запущены процессы. После показа остановите **свои** сервисы из этого checkout: `.\scripts\stop.ps1`. Базу не удаляйте и не перезаписывайте ради повторной репетиции.

### Linux

```bash
# Из корня отдельного checkout; все команды в одном shell.
mkdir -p .cache
demo_dir="$(mktemp -d "$PWD/.cache/battle-XXXXXXXX")"
export DATABASE_URL="sqlite:///$demo_dir/runtime.sqlite"
export ASBOLJAM_ENV=local DEMO_DATASET=kz COOKIE_SECURE=false
export ALLOWED_ORIGINS='http://localhost:3000,http://127.0.0.1:3000'
export ASBOLJAM_SELF_REGISTRATION=on WEATHER_PROVIDER=off LOKY_MAX_CPU_COUNT=1
# Вывод Python захватывается переменной, пароль не выводится в консоль.
export DEMO_PASSWORD="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
bash scripts/start.sh --install
unset DEMO_PASSWORD
cat .cache/processes.pid
cat .cache/logs/api.err.log .cache/logs/worker.err.log .cache/logs/web.err.log
curl --fail http://127.0.0.1:8000/api/v1/ready
curl --fail --silent --output /dev/null http://localhost:3000
git check-ignore .cache/battle-demo-login.json
# Только после проверки процессов именно этого запуска и выбранной базы:
export PREDAS_DEMO_ISOLATED=1
npx playwright install chromium ffmpeg
node scripts/prepare_battle_demo.mjs --lang ru
```

Для подготовки зависимостей Linux cloud checkout существует `bash scripts/cloud_setup.sh`. Он не запускает приложение и не подтверждает изоляцию базы; после него задайте переменные для новой базы и выполните `bash scripts/start.sh`. При отсутствии системных библиотек браузера используйте предусмотренную `cloud_setup.sh` установку Chromium с зависимостями. Для остановки собственных сервисов — `bash scripts/stop.sh`.

### Что делает подготовка

```text
node scripts/prepare_battle_demo.mjs --lang ru
node scripts/prepare_battle_demo.mjs --lang kk
node scripts/prepare_battle_demo.mjs --url http://127.0.0.1:3000 --lang ru
```

Скрипт через Playwright регистрирует новое **Кафе «Достар»**, тип **Кафе**, город **Алматы**, уникальную почту `demo-<random>@example.invalid` и случайный сильный пароль. Затем нажимает существующую кнопку **«Загрузить демо-данные»**, строит прогноз на **01.01.2026**, закрывает учебный день с явными порциями по каждому блюду и рассчитывает закупку. Проверки формы и API сохраняются; неподтверждённый результат считается ошибкой.

Почта печатается в консоль, пароль не печатается. Полные данные для входа сохраняются **только в `.cache/battle-demo-login.json`**, исключённом из Git. Повтор запуска создаёт другой кабинет и заменяет этот локальный файл данными последнего кабинета; предыдущие организации и базы не удаляются. Не включайте файл в коммит, презентацию, переписку или снимки экрана.

Откройте файл локально вне трансляции, скопируйте почту и пароль, затем на `http://localhost:3000` выберите русский язык и войдите через поля **«Электронная почта»**, **«Пароль»** и кнопку **«Войти в систему»**. Закройте файл перед показом. Не выводите JSON через консоль, общую с записью экрана.

### Последняя репетиция перед сценой

Подготовка уже **закрывает** день и создаёт **неутверждённую** закупку. Для показа повторного подтверждения фактов заранее откройте этот же день через реальный интерфейс:

1. **Сегодня → Закрыть день → Открыть для исправления**.
2. В поле **«Почему открываете снова?»** укажите `Репетиция синтетической демонстрации`, нажмите **«Открыть снова»**.
3. Сохранённые порции, цены, флаги меню, отсутствия акции и окончания блюд оставьте без изменения. Это реальный черновик повторного закрытия, а не первое внесение фактов. Не меняйте продажи ради красивого сравнения. Возврат на **«Сегодня»** не должен требовать отказа от несохранённых правок.
4. Проверьте доступность сохранённого прогноза на **01.01.2026** и готовой закупки. Не утверждайте её на репетиции: утверждение будет показано на сцене. Если факты или исходные данные действительно менялись, выполните требуемый интерфейсом пересчёт и проверьте актуальность заранее.
5. Вернитесь к экрану входа. Подготовьте значения для быстрой вставки вне трансляции, закройте парольный файл и включите таймер.

Повторное закрытие с **точно теми же фактами** не складывает продажи повторно. Возникают версия закрытия и запись аудита. Если видите конфликт, требование причины исправления или блокировку актуальности, разберите их до выступления; не обходите проверки. Для полного первого заполнения всех блюд используйте свежий кабинет в записи резервного видео. После успешного питча для ещё одной репетиции создайте новый кабинет: утверждённый план нельзя выдавать за ожидающий решения.

## 2. Точный маршрут: 180 секунд

Основной маршрут: **Вход → Сегодня → Прогноз → Закрыть день → Прогноз и фактические продажи (если доступно) → Закупки → Утвердить план → Профиль**. Расчёты заранее проверены, на сцене открываются их сохранённые результаты. Если операция не успевает закончиться в своё окно, переходите к резервному видео, не объявляя успех.

| Время | Действие в существующем интерфейсе | Что должно быть видно | Одна фраза выступающего |
| --- | --- | --- | --- |
| **00:00–00:15 — 15 с** | Вставить подготовленные значения в **«Электронная почта»**, **«Пароль»**, нажать **«Войти в систему»**. | Кабинет **Кафе «Достар»**, Алматы; пароль скрыт. | «Это учебное кафе: все показанные данные синтетические». |
| **00:15–00:35 — 20 с** | Нажать **«Сегодня»** в верхней навигации. | Учебная дата **01.01.2026**, следующий шаг и цепочка прогноза, остатков, закупки и решения. | «Управляющий сразу видит, что требуется для подготовки рабочего дня». |
| **00:35–01:00 — 25 с** | **«Прогноз» → «Открыть прогноз дня»**. | Заголовок **«Прогноз на 01.01.2026»**, порции по блюдам, выбранный метод и отметка SYNTHETIC. | «По истории продаж Predas рассчитывает ориентир порций для каждого блюда». |

| **02:10–02:35 — 25 с** | **«Закупки» → «Открыть закупку дня»**. | Сохранённая закупка на **01.01.2026**, поставщики, упаковки, стоимость, бюджет и возможный дефицит. | «Закупка связывает прогноз, рецептуры, пригодные остатки и упаковки поставщиков в пределах бюджета». |

### Если показываете первое закрытие на свежем кабинете

Полный ввод требует репетиции и может занять больше 50 секунд. Не пытайтесь ускорить его подменой ответа API. На странице **«Закрыть день»**:

1. **«Да, работало»**.
2. Последовательно **«Все блюда были в меню»**, **«Ничего не закончилось»**, **«Акций не было»**, **«Цены по меню»**.
3. Для **каждого** блюда явно заполнить **«Продано, порций»** и **«Было готово, порций»** целыми учебными значениями. Второе поле — **всё доступное количество**, не остаток после продажи: например, продано 24, было готово 30. Всегда `0 ≤ продано ≤ было готово`; пустое поле не равно нулю.
4. **«Проверить»**, убедиться в отсутствии незаполненных строк и нажать **«Закрыть день» именно в карточке «Проверьте перед закрытием»**.

## 3. Резервное видео и аварийный сценарий

После проверки изоляции, с работающими web, API и worker, в том же терминале:

```text
npx playwright install ffmpeg
node scripts/record_demo_video.mjs --lang ru
node scripts/record_demo_video.mjs --lang kk
```

В PowerShell при ограничении выполнения `npx.ps1` используйте `npx.cmd`. Скрипт сначала пробует установленный Google Chrome, затем bundled Chromium Playwright. Если оба отсутствуют, установите Chromium командой `npx playwright install chromium`. Запись создаёт **новый** учебный кабинет и выполняет регистрацию, загрузку данных, прогноз, полное первое закрытие дня, сверку при наличии, склад, закупку, утверждение и профиль. Сохранены титры, видимый курсор и снимок при ошибке; неподтверждённые операции не считаются успехом.

Готовый файл: **`.cache/demo-video/predas-demo-ru.webm`** или **`predas-demo-kk.webm`**. Дополнительные параметры: `--url http://localhost:3000` и `--out .cache/demo-video`. Сохраняйте видео и снимки в игнорируемой `.cache`, не добавляйте их в Git. При ошибке `failure.png` служит для локального разбора; не выдавайте частичную запись за готовый ролик.

До выступления **откройте WebM целиком в браузере или плеере**: проверьте начало, закрытие дня, результат утверждения, финальный профиль и читаемость титров. Запись экрана не гарантирует длительность ровно 180 секунд: тайминг ручного выступления приведён отдельно. Сделайте локальную копию видео на ноутбуке и на резервном носителе, проверьте воспроизведение без сети, полноэкранный режим и переход с браузера на плеер. Не рассчитывайте на скачивание во время питча.

Заранее сохраните читаемые снимки без почты, пароля и открытого меню аккаунта:

- **Сегодня** с учебной датой и цепочкой работы.
- **Прогноз на 01.01.2026** с порциями блюд и отметкой SYNTHETIC.
- **Проверьте перед закрытием** и подтверждение **«День закрыт»** с закрывающим пользователем, скрытым или обрезанным.
- **Прогноз и фактические продажи**, если доступно, с предупреждением об учебном характере.
- Строки закупки, стоимость, бюджет и дефицит; затем сведения об утверждении без идентификатора входа.
- Верхняя часть профиля с названием, городом и типом заведения; не включать блок доступа с почтой.

Если сайт, API или worker недоступен, отведите на проверку не более нескольких секунд и скажите: **«Стенд сейчас недоступен; покажу заранее записанный тот же процесс на синтетических данных»**. Откройте локальный ролик с нужного эпизода. Если видео тоже не воспроизводится, пройдите маршрут по подготовленным снимкам и объясните связь входных данных с решением управляющего.

При зависшем worker страница может открываться, но новый расчёт не готов: показывайте сохранённые подтверждённые результаты или видео, не объявляйте запущенное задание успешным. При недоступном backend используйте локальные материалы; не ослабляйте валидации, не меняйте рабочую базу и не подменяйте реальные ответы. До следующего показа восстановите сервисы и повторите подготовку на проверенной отдельной базе.

## 4. Проверки перед передачей

Команды выполняются на том же изолированном стенде. Для browser-набора требуется отдельная учебная фикстура:

```text
node scripts/prepare_battle_demo.mjs --lang ru
node scripts/record_demo_video.mjs --lang ru
npm run build
python scripts/prepare_e2e.py
```

При установленном Python virtualenv используйте его интерпретатор: `.venv/Scripts/python.exe` в Windows или `.venv/bin/python` в Linux. `prepare_e2e.py` тоже пишет данные, поэтому для него обязательны те же переменные окружения с новой `.cache`-базой.
