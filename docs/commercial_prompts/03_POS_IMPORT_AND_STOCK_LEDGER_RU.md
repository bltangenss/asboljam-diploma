# Этап 3: реальные POS-данные и складской контур

Работай в существующем AsBoljam по `00_MASTER_COMMERCIAL_VERSION_RU.md`. Входом служат согласованные правила этапов 1–2.

## Цель

Дать первому бизнесу повторяемый и объяснимый путь из реального POS/ERP-экспорта в прогноз и закупочный план, сохранив контроль человека и возможность отката ошибочного импорта.

## Задачи

1. Реализуй адаптер через versioned mapping profile, а не через жёсткую привязку к одному поставщику POS. Исходный файл не изменяй.
2. Поддержи dry-run, preview, валидацию, idempotency key, duplicate detection, partial-error report и транзакционный commit.
3. Добавь origin evidence: источник, период, branch, timezone, mapping version, file hash, row counts и operator. Не записывай исходные персональные поля.
4. Расшири inventory от snapshot к явному движению: приход, списание, корректировка, продажа/расход по рецепту, lot, expiry и причина. Сохрани snapshot-совместимость для демо.
5. Проверь активную версию рецептуры, yield и единицы. Нельзя дважды применять yield или смешивать kg/L/шт.
6. Обнови forecast и procurement так, чтобы расчёт показывал входные даты, модель, рецепт, остаток, lead time, бюджет, упаковки, дефицит и причину.
7. Подготовь безопасный rollback/reconciliation workflow: ошибочный файл помечается, корректирующая загрузка создаёт audit trail, старые подтверждённые решения не переписываются.
8. Добавь один обезличенный pilot fixture, созданный искусственно из согласованной схемы. Реальные файлы клиента храни только вне репозитория.

## Критерии приёмки

- Один и тот же файл повторно не удваивает продажи или остатки.
- Ошибка в одной строке не меняет operational rows, если commit не разрешён политикой частичного импорта.
- Актуальный stock ledger сверяется с snapshot и показывает дату/причину расхождения.
- Forecast использует только разрешённые прошлые observed sales; procurement использует точный snapshot/ledger и действительные offers.
- Пользователь видит понятный импортный отчёт и может связать закупочную строку с исходными данными.

## Обязательная проверка

Выполни адаптер/importer tests, один end-to-end pilot fixture и проверки математических ограничений. Не запускай автоматическую отправку поставщику: это отдельный этап с отдельным разрешением.
