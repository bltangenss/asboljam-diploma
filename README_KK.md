# AsBoljam

Асхана/кафе менеджеріне арналған оқу жүйесі: сатылымды импорттау → біркүндік болжам → ингредиент қажеттілігі → қойма → сатып алу жоспары → менеджер шешімі. Интерфейс тілі — қазақша. Барлық берілген дерек **SYNTHETIC**. Сценарий күні **01.01.2026**, тарих соңы **31.12.2025**.

## Іске қосу

Тексерілген әзірлеу ортасы: Python 3.13.9, Node.js 24.14.1. Жоба түбірінде PowerShell ашыңыз:

```powershell
.\scripts\start.ps1 -Install
```

Бірінші іске қосқанда тәуелділіктер орнатылады, миграция орындалады, тоғыз CSV жүктеледі. API, worker және web жасырын фондық процестерде іске қосылады. Мекенжай: **http://localhost:3000**.

Әкімші поштасы: **admin@asboljam.local**. Қауіпсіз кездейсоқ құпиясөз CLI-де **бір рет** көрсетіледі; оны сақтаңыз. Өз құпиясөзіңізді таңдау үшін алдын ала `DEMO_PASSWORD` орта айнымалысын беріңіз: кемінде 12 таңба. Бастапқы кодта дайын пароль жоқ. Seed-ті қайталау қолданыстағы құпиясөзді өзгертпейді.

```powershell
.\scripts\start.ps1
.\scripts\stop.ps1
```

Журналдар: `.cache/logs/`. API құжаттамасы: `http://127.0.0.1:8000/docs`. 3000 және 8000 порттары бос болуы керек. PowerShell саясаты скриптті бұғаттаса, [орысша нұсқаулықтағы](README_RU.md) қолмен іске қосу пәрмендерін қолданыңыз.

Linux/macOS:

```bash
bash scripts/start.sh --install
bash scripts/stop.sh
```

`start.sh` арқылы Linux/macOS хостында толық іске қосу тексерілген жоқ; Docker Linux контейнерлеріндегі тексеру төменде бөлек көрсетілген. Қолмен іске қосқанда Python жолы `.venv/bin/python`, Windows-та `.venv/Scripts/python.exe`. Үш бөлек процесс қажет: `python -m uvicorn apps.api.main:app --port 8000`, `python -m apps.worker.main`, `npm run dev`. Worker болмаса, есептер `queued` күйінде қалады.

## Docker

`.env.example` файлын `.env` етіп көшіріп, `POSTGRES_PASSWORD` үшін жеке URL-safe кездейсоқ мән беріңіз. Docker daemon іске қосылған болуы керек.

```powershell
docker compose up --build -d
docker compose exec api python scripts/seed_demo.py
```

Веб: `http://localhost:3000`. PostgreSQL дерегі named volume-де сақталады. Құпиясөзді репозиторийге қоспаңыз. Docker ішінде API/worker/web және PostgreSQL 17.11 іске қосылды; бөлек тексеру жобасында 18 API тесті сәтті өтті. Нақты нұсқалар, дерек саны және image ID — [PostgreSQL тексеру артефактісінде](artifacts/verification/postgres.json). Тексеру жобасы 3010/8010 порттарын қолданды; жоғарыдағы қалыпты іске қосу 3000/8000 порттарын қолданады. Бұл public deployment, TLS немесе production жүктеме сынағы емес.

Nginx арқылы сыртқы HTTP сценарийі бөлек worker-пен орындалды: [runtime.json](artifacts/verification/runtime.json) ішінде 77 сәтті тексеру және олардың шектеулері бар. PostgreSQL dump жаңа базаға қалпына келтірілді; кестелердегі жазба саны, password hash және миграция сәйкес келгені [backup артефактісінде](artifacts/verification/postgres-backup.json) тіркелген. Dump файлының өзі құпия дерек ретінде Git/ZIP-тен тыс қалады; production ортадағы қалпына келтіру бөлек тексеріледі.

Жергілікті әдепкі қойма: `data/asboljam.sqlite`. `start` скрипттері `.env` файлындағы бос емес `KEY=VALUE` жұптарын оқиды. HTTPS ортада `COOKIE_SECURE=true` және нақты `ALLOWED_ORIGINS` қажет. Жария орналастыру орындалған жоқ.

## Негізгі сценарий

1. Кіру және бөлімшені таңдау.
2. Сатылым тарихын, күн және тағам сүзгілерін тексеру.
3. CSV алдын ала тексеруін ашып, қателерді қарау және жарамды импортты растау. Қайталанған кілттер қабылданбайды.
4. `2025-12-31` origin бойынша болжам есептеу; бөлек worker нәтижесін күту.
5. Болжам мен бюджеттен сатып алу жоспарын есептеу; қорды, қаптамаларды, шығынды және тапшылықты тексеру.
6. Менеджер/әкімші шешімін тіркеу. Тапшылық бар болса, арнайы растау керек. CSV экспортын және аудитті тексеру.

Seed тоғыз бастапқы CSV-ді жүктеп қойған. Оларды қайта импорттау дубликат қатесін көрсетуі тиіс. Жаңа импорт үшін анықтамалық сілтемелері жарамды жаңа табиғи кілт қолданыңыз. Бастапқы тарихи деректі өзгертпеңіз.

Жоспарды бекіту — ішкі шешім; жеткізушіге тапсырыс жіберілмейді. MVP көкжиегі — бір күн. Бүгінгі күнге шынайы жоспар үшін жаңа сатылым және қойма кесіндісі қажет.

## Тексеру және зерттеу

```powershell
python -X utf8 -m unittest discover -s tests -v
npm.cmd run build
npm.cmd run test:e2e
python -X utf8 scripts/run_research.py
```

Python, PostgreSQL, web, браузер және native тексерулерінің соңғы саны мен орындалған пәрмендері [қорытынды есепте](FINAL_REPORT.md) және [PROGRESS.md](templates/PROGRESS.md) тіркеледі. Мұнда жалпы test санын қайталамаймыз: жаңа тексерулер қосылғанда бір негізгі есеп жаңартылады. Команданың жазылуы оның сәтті орындалғанын білдірмейді.

Нақты есептелген нәтижелер: 9 болжам, 36 сатып алу сценарийі; тест кезеңі 04.12.2025–31.12.2025, әр бөлімшеде 336 бақылау. [Зерттеу нәтижелері](artifacts/research/README_KK.md) және [шығу тегі](artifacts/research/provenance.json). Бұл нақты кәсіпорындағы экономикалық үнемнің дәлелі емес. HGB p10–p90 номинал аралығы — 80%; базалық модельдерде квантильдер жоқ.

## Іске асыру шешімдері

Web: React/TypeScript/Vite; бастапқы ұсыныстағы Next.js қолданылмады. Backend: FastAPI/SQLAlchemy. Жеке worker БД-дағы тұрақты кезекті оқиды; Celery/Redis қолданылмайды. Миграция `0001` — жеке механизм, Alembic емес. Операциялық CSV жазбалары валидтелген JSON түрінде, ұйым/бөлімше және бірегей кілтпен сақталады; сілтемелер импорт транзакциясында тексеріледі.

Толық қойма қозғалысы, кассаға тікелей қосылу, рецепттің белсенді нұсқасын алмастыру және автоматты тапсырыс іске асырылмаған. Oracle пен генератор параметрлері модель белгілеріне және API-ге кірмейді. Қолданбаның импорты `SYNTHETIC` және `kg`/`L` схемасын қолдайды.

[Офлайн POS адаптері](docs/POS_ADAPTER_RU.md) сатылым мен қойма CSV бағандарын айқын сәйкестендіріп, күндерді, бірліктерді, Decimal мәндерін және дубликаттарды тексереді. Әдепкі режим — файл жазбайтын dry run. `--write` нәтижені тек Git елемейтін `.cache/enterprise-adapter` ішінде жаңа каталогқа сақтайды. `REAL` дерегі `REAL` болып қалады; оны қолданбаға енгізу әдейі қолдау таппайды. Мысалдар жасанды, нақты кәсіпорынмен үйлесімділік тексерілмеген. Белгілі жеке/oracle өрістер қабылданбайды, бірақ бұл толық жеке дерек аудитін алмастырмайды; нақты дерек пен output-ты Git/ZIP-ке қоспау керек. Зерттеу скрипті тек айқын `SYNTHETIC` кірістерді қабылдайды.

Expo/React Native бастапқы коды `apps/mobile` ішінде. Құрылғыдағы тексеру және APK/IPA құрастыруы бөлек белгіленеді; бастапқы код дайын дүкендік релизге тең емес.
