## 2. Источник продаж

- [ ] POS/ERP и версия экспорта названы.
- [ ] Определена бизнес-дата и граница смены.
- [ ] Понятно, как отражаются возвраты, отмены, списания, комплекты и модификаторы.
- [ ] Продажи агрегируются по филиалу и блюду.
- [ ] `units_sold` означает наблюдаемые проданные порции.
- [ ] `available_portions` и `stockout_flag` берутся из источника, а не вычисляются из продаж.
- [ ] Акции и фактическая цена имеют согласованный смысл.
- [ ] Нет клиентов, телефонов, email, карт, сотрудников и свободного текста.

## 3. Меню и рецептуры

- [ ] Есть стабильные `meal_id` и `ingredient_id`.
- [ ] Для активного меню указана версия рецептуры.
- [ ] На каждую порцию указана базовая единица и net quantity.
- [ ] Yield подтверждён технологом/ответственным и не применяется повторно.
- [ ] Сезонные, отключённые и новые блюда имеют дату действия.

## 4. Склад и закупки

- [ ] Остаток дан как snapshot или согласованный журнал движения.
- [ ] Для партии есть `lot_id`, snapshot date и expiry date, если применимо.
- [ ] Единицы kg/L/шт согласованы с ингредиентами; скрытая конвертация запрещена.
- [ ] Для каждой закупаемой позиции есть поставщик, упаковка, цена, MOQ, max packs и lead time.
- [ ] Известны бюджет и ограничение хранения на цикл закупки.

## 5. Доступ и конфиденциальность

- [ ] Есть письменное разрешение на обработку агрегированных операционных данных.
- [ ] Определены срок хранения, оператор загрузки и порядок отзыва доступа.
- [ ] Реальные исходники и mapping хранятся вне репозитория.
- [ ] В Git/ZIP попадут только synthetic fixture, схема и обезличенные отчёты.
