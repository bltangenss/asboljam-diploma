# Этап 2: коммерческая изоляция и безопасность

Работай в существующем AsBoljam по `00_MASTER_COMMERCIAL_VERSION_RU.md` и используй договор данных из этапа 1.

## Цель

Сделать безопасную основу для нескольких организаций и филиалов, сохранив простой сценарий первого клиента. Пользователь одной организации не должен видеть или менять данные другой организации; доступ к филиалам и ролям должен проверяться на API, а не только в UI.

## Задачи

1. Проведи аудит всех read/write endpoint, фоновых job, экспортов и download events на organization, branch и role scope.
2. Зафиксируй модель tenant: организация, филиал, пользователь, роль, разрешённые филиалы, статус, timezone и настройки происхождения данных.
3. Добавь явные миграции и индексы только там, где это требуется. Existing SQLite и PostgreSQL должны мигрировать предсказуемо.
4. Проверь web cookie/Origin/CSRF, native access/refresh rotation, отзыв сессий после изменения доступа, rate limits, безопасные ошибки и отсутствие секретов в логах.
5. Проверь import, forecast, procurement, approval, audit и export на cross-tenant/cross-branch leakage. Особое внимание удели background worker input snapshots.
6. Введи production-конфигурацию: HTTPS-only cookies, конкретные allowed origins, secure headers, CORS, secret injection и запрет debug-секретов. `.env.example` оставь безопасным.
7. Добавь короткую security runbook: создание tenant, добавление пользователя, отзыв доступа, резервное копирование, реагирование на утечку токена и удаление tenant по договору.

## Критерии приёмки

- API-тесты доказывают запрет чтения и изменения чужой организации и филиала для каждой важной операции.
- Менеджер не может менять справочники/пользователей вне роли; analyst остаётся read-only.
- Worker не выполняет job после отзыва доступа или для чужого scope.
- Audit содержит actor, tenant, branch, action, object, reason/version и timestamp без токенов и паролей.
- Секретная проверка проходит, а demo запуск остаётся воспроизводимым.

## Обязательная проверка

Запусти изменённые API/security tests и миграционный smoke на SQLite и PostgreSQL, если менялась схема. Не называй независимым security audit набор локальных тестов.
