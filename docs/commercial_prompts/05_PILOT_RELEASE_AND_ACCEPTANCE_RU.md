# Этап 5: пилот, измерение и коммерческий выпуск

Работай в существующем AsBoljam по `00_MASTER_COMMERCIAL_VERSION_RU.md` после завершения этапов 1–4.

## Цель

Провести ограниченный пилот одного реального филиала и получить проверяемое решение о продолжении, доработке или остановке. Пилот не должен превращаться в скрытую публикацию или обещание экономии.

## Задачи

1. Зафиксируй письменный pilot charter: организация, филиал, период, ответственные, разрешённые данные, retention, support channel, критерии остановки и способ отзыва доступа.
2. Сделай baseline до использования системы: закупочные расходы, списания, stockout, out-of-stock meals, ручное время планирования, forecast error и период наблюдения.
3. Запусти shadow mode: AsBoljam формирует рекомендацию, менеджер сравнивает её с фактическим решением, но система не отправляет заказ автоматически.
4. Для каждого цикла сохраняй входной hash, модель, forecast date, procurement inputs, approval, фактическую закупку/остаток и расхождение. Публикуй только агрегаты, разрешённые договором.
5. Проведи UAT по полному сценарию: login → import → preview → commit → sales → forecast → recipes/inventory → procurement → approval → audit/export → backup/restore.
6. Собери feedback владельца и оператора: понятность, время, ошибки, missing data, доверие к дефициту и причины ручной корректировки.
7. Сформируй release checklist: версия, миграции, rollback, backup, secrets, HTTPS, support contacts, known limitations, release notes и архив доказательств.
8. Оцени результат только по заранее согласованным метрикам. Если данных мало или дизайн измерения не позволяет сделать вывод, напиши `insufficient evidence`.

## Критерии приёмки

- Пилот можно воспроизвести на согласованном периоде с сохранённым provenance.
- Каждый approval сделан человеком и виден в аудите; автоматического supplier order нет без отдельного согласования.
- Метрики сравниваются с baseline одинаковым способом и не подменяются synthetic результатами.
- Есть решение владельца: продолжить, доработать или остановить, с причинами и открытыми рисками.
- Release package не содержит данные клиента, секреты, БД, browser traces или APK, если они не нужны и отдельно не разрешены.

## Обязательная проверка

Выполни только доступный UAT и regression scope, фактически подключённый к пилоту. Для Android/iOS release и магазинной публикации создай отдельную задачу; debug APK не считай коммерческим выпуском.
